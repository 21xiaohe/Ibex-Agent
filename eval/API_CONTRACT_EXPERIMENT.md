# 固定维护契约：FastAPI 小范围实验

目的：检查“内部测试通过但实际需求未满足”的问题，优先改进一个明确场景，而不是继续扩展渠道或 Agent 角色。

## 实验前固定的规则

- 两个新 API 任务变体：运费计算 `/shipping-quote`、预约时段校验 `/booking-check`。完整需求在 `api_contract_cases.py` 的 REQUEST 常量中。它们复用金额/校验等能力，不是统计独立的新领域。
- 两种流程：现有模型生成契约，以及预先维护的固定契约。各任务各流程一次，共 4 次；不挑最好一次、不因失败调整题目后覆盖成绩。
- 顺序：运费自动 → 运费固定 → 预约固定 → 预约自动，第二题反转流程顺序。
- 相同模型配置、单 Agent、标准 Docker、temperature=0、每次 300 秒、图上限 80。每次创建独立沙箱。
- 固定流程会告知 Agent 可调用 `verify_changes` 获取固定契约反馈。因此比较的是整个验证流程，不是只替换测试来源的严格消融。
- 固定契约由编码助手预先编写，并通过参考实现和语义错误负例检查，**未经用户或其他人类审核**；不写成“人工验收契约已审核”。参考实现只在 `tests_service/`，不会注入候选沙箱。
- 外部验收使用另一组具体样例，只在生成结束后运行，不作为修复反馈。两套测试与参考代码由同一助手编写，仍有共同盲点；不能称双盲或独立专家评审。
- 外部评分沿用 `run_objective.run_trial`：目标产物存在、验收退出码 0、所有断言通过。超时、图上限、接口异常都计失败。账号错误立即停止，记录 incomplete，不继续付费重试。
- 两题一次重复只提供诊断信号，不证明稳定成功率，也不能与历史 6 题 2/12 直接比较。主 Agent token 统计未完整包含自动契约调用，不能直接比较账单成本。

## 固定契约机制

`MaintainedContract` 是控制端显式传给 `build_agent_for_service(..., maintained_contract=...)` 的不可变对象，绑定精确需求文本与测试哈希。没有修改公共 API 接口接受可执行测试；也不会根据关键词自动套用不相关契约。目前限定单 Agent、可执行沙箱。

需求不匹配或契约格式错误直接阻塞，不能静默退回 project_only。测试源码保存在控制端，验证时注入临时文件；每次重新注入，仍检查修改后的文件指纹和项目测试。失败反馈包含固定测试信息，这是允许的训练式修复反馈；外部验收保持不可见。通过范围记为 `maintained_contract_and_project`，不承诺完整需求覆盖或抵御恶意篡改。

自检包括：真实失败实现触发纠正、修复后通过且不调用模型生成契约；错误需求绑定拒绝；固定与外部测试接受参考实现，分别拒绝每题 3 类语义错误（舍入、类型、额外字段、日期、边界）。自检中禁用 Python 字节码缓存，避免连续改写负例时运行旧版本。

## 运行

```bash
python -m eval.run_api_contracts --output logs/api-contracts-run-001.json
```

这是付费模型实验入口，默认不是 Web 产品流程。源码提交和任务哈希在真实运行前冻结，运行器保存配置、源码哈希、全部试次及诊断。实验结果与后续限制将追加到本文，旧结果不覆盖。

## 结果

| 任务 | 流程 | 结果 | 耗时 |
| --- | --- | --- | --- |
| 运费接口 | 自动契约 | 300 秒任务超时；自动契约 JSON 解析失败后已降级 | 300.245 秒 |
| 运费接口 | 固定契约 | 固定测试发现 JSON 请求体被写成查询参数；返回失败反馈后出现 BadRequestError | 35.833 秒 |
| 预约接口 | 固定契约 | 固定测试发现 bool 被接受为整数；最终达到图执行上限 | 141.359 秒 |
| 预约接口 | 自动契约 | 模型接口 APITimeoutError | 165.160 秒 |

**自动契约 0/2；固定契约 0/2。** 全部计划试次执行完毕，`complete=true`，命令退出码 1。没有失败试次重跑，也没有改题后覆盖结果。

四次都在进入外部验收前终止，因此这里没有“外部验收通过”或“外部验收发现错误”的候选结果，不能用 0 个假阳性声称减少了假阳性。固定流程两次都实际运行了契约，发现需求违背，均未将失败报告为通过；但没有验证到“反馈 → 修复 → 外部验收通过”的完整路径。

这轮没有观察到成功率提升。模型接口异常使结果不能简单归因于代码能力；BadRequestError 的原始响应未保存，原因尚未确定，不能称为欠费、协议错误或模型拒绝。较短的失败耗时也不代表更高效率，不能拿失败提前结束来宣称节约成本。

## 本轮结论与下一步

已交付：控制端显式固定契约、精确需求绑定和哈希、失败阻断及纠正反馈；两个 API 的契约/外部样例与参考及错误负例自检；一轮完整真实模型对照。

没有完成：证明自动开发质量改善、证明真实模型能依反馈修复、证明固定契约覆盖完整需求。功能保持显式实验入口，不替换所有用户请求的默认自动契约流程。

后续应先补模型接口错误的脱敏分类/请求结构诊断，并检查纠正阶段的消息协议及图预算消耗；然后对一个任务尝试固定的“生成 → 执行验收 → 最多有限次修复”流程，限制无关规划和工具循环。是否换模型通过另一个固定条件对照回答。本轮没有开展这些额外实验，也没有扩大付费试次。
